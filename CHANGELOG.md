# Changelog

What changed in each version of WikiGuard. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Until 1.0.0 the minor number is the build phase that the version completes, so 0.6.0 is the end
of Phase 6. 1.0.0 is the launch, after production hardening. Versions before 0.6.0 were written up
afterwards from the commit that finished each phase, and the links below point at those commits.

To release: move the notes under "Unreleased" to a new version heading, merge, wait for the CD
workflow to publish that commit's images, then push a `vX.Y.Z` tag. The release workflow gives the
tested images the version name and publishes these notes.

## [Unreleased]

### Added
- Full CI on every pull request: lint, types, the whole Python suite on real Postgres and
  Redpanda with a coverage gate for each part, the trainer's tests and a training smoke test on
  CPU PyTorch, a Compose end-to-end run, an image build and Trivy scan for every image, the
  frontend checks, `pip-audit`, `npm audit`, gitleaks, and CodeQL.
- Path filters, so a pull request runs only the jobs its files can affect, and one `ci` check for
  branch protection to require.
- Hash-locked Python installs. Each `requirements.in` compiles to a `requirements.txt` that pins
  every package with its SHA-256 (`scripts/lock_requirements.py`), and images and CI install with
  `--require-hashes`.
- A CD workflow: after CI passes on `main`, every image is built for amd64 and arm64 on native
  runners, scanned, and published to GHCR. It then migrates and deploys staging, smoke-tests it,
  and repeats for production. The deploy half stays off until Phase 7 creates the services.
- A deploy smoke test (`scripts/smoke_test.py`) that waits for the new build and checks it's
  still locked. `/health` now reports the commit it was built from.
- API fuzzing from the OpenAPI schema with Schemathesis, in the test suite and as a scan of
  staging, next to an OWASP ZAP baseline scan.
- A test that keeps migrations to expand-then-contract, so the running code never breaks
  during a deploy.
- A release workflow, this changelog, and Dependabot for Actions, base images, Python, and npm.
- `/robots.txt`, which closes `/api/` to crawlers.
- The cluster (Phase 7): a Helm chart for Redpanda, the ingestor, scorer, and archiver, every
  scheduled job, and the trainer Job template, with priorities so scoring always beats training.
  Production values for k3s on the Oracle VM, and kind values for the laptop
  (`scripts/kind_cluster.py`).
- Pod Security `restricted` for every WikiGuard pod, default-deny NetworkPolicies in both
  directions with a per-component allowlist, one Secret per component, Sealed Secrets for GitOps,
  and the poller as the only pod with an API token. `tests/test_k8s_chart.py` checks every pod, and
  `scripts/check_network_policies.sh` checks a running cluster enforces the policies.
- The retrain poller starts each request as a Kubernetes Job from the chart's template.
- A trainer image with CPU PyTorch, locked separately for amd64 and arm64.
- A nightly backup of the tables that can't be rebuilt, encrypted to a public key, with 7 daily
  and 4 weekly copies, and a restore that rebuilds the last 3 days from the archive
  (`jobs/backup`). A read-only role for it, and one for Grafana (migration 0005).
- The archive on S3-compatible storage, and a nightly mirror of the working copy to the bucket
  (`archiver.py --mirror`, `--restore-mirror`).
- Prometheus, Alertmanager, and Grafana (kube-prometheus-stack), alert rules for the pipeline,
  jobs, disk, and Oracle's idle rule, Discord and Healthchecks.io delivery, and five dashboards
  generated by `scripts/build_dashboards.py`.
- Argo CD apps, and a one-command bootstrap and a hardening script for the VM.
- CD opens a pull request that pins the cluster's image digests (`CLUSTER_ENABLED`).
- The Cloudflare Worker (`edge/`): the single site address, with an edge rate limit.
- `render.yaml` for the API on Render, production and staging, with the models built into the
  image (`PREFETCH_MODELS`).
- Error tracking with Sentry in the API and the workers, off unless `SENTRY_DSN` is set, with
  request data, local variables, and quoted rows removed before an event leaves.
- CI imports every module each image runs, inside that image, and renders the chart with Helm.
- `scripts/load_demo.py` loads the public demo's data: the snapshot's 25,294 test-window edits,
  with the champion's stored test score and the real revert label for each.
- The API's `DATA_MODE` setting. With `snapshot`, the queue and feed show the whole dataset with no
  time window, and the health summary counts the dataset; `/v1/queue`, `/v1/feed`, and
  `/v1/health/summary` say which mode they're in.
- Local builds give their disk space back: `kind_cluster.py` deletes the host's image copies once
  they're in the node and, at `down`, the node's volume; the Compose test stacks delete the images
  they built; all prune the unused build cache. `--keep-images` keeps them.
- On snapshot data, every console page says "Demo data: ... Not live.", and the status pill reads
  "Snapshot, not live".

### Changed
- Scope: no free server can run the pipeline around the clock, so the public demo serves a scored
  snapshot of real edits, and the streaming pipeline and the Kubernetes chart run locally on kind.
  The Oracle VM is no longer part of the plan.
- "Live feed" is now "Edit feed", and the landing page, privacy notice, and 404 page describe the
  demo's data as it is.
- Every Dockerfile is now two stages on a base image pinned by digest. Compose images are pinned
  by digest too.
- The published API schema now describes validation errors as `application/problem+json`, which
  is what the API always sent. The frontend's generated types changed to match.
- A `.dockerignore` keeps everything except the code out of image builds.
- The API reads the visitor's address from the Worker's own `x-wikiguard-client-ip` header, still
  only with the edge secret, instead of `cf-connecting-ip`.
- Frontend: Next.js 16.4.6, React 19.3.1, jsdom 31, and four other patch and minor updates.
  The frontend is installed with npm 11.21.2 (`packageManager`), the npm Dependabot uses, in CI
  too. Dependabot no longer offers Python past 3.11, Postgres past 17, or majors of TypeScript,
  ESLint, and `@types/node` that the toolchain can't take yet.

### Fixed
- Every Dependabot frontend pull request failed `npm ci`: Dependabot writes lock files with npm
  11, and CI installed with Node 22's npm 10, which wants entries npm 11 leaves out.
- Two trainer tests that failed on Linux runners for toy-model numerics, not a bug.
- `/favicon.ico` and `/robots.txt` answered with a 404 page that had no Content-Security-Policy. Found by OWASP ZAP.
- The HTTP client's request log, which wrote whole URLs, including usernames and, in the jobs that
  alert, the Discord webhook and Healthchecks.io URLs. Its records below WARNING are now dropped.

### Security
- Workflows hold no secrets on pull requests, use a read-only token by default, and pin every
  action to a commit. Tests in the suite fail if a workflow, Dockerfile, or lock file breaks
  these rules.
- CD's jobs that check out the tested commit also require it to come from this repository, and
  the end-to-end stacks' throwaway credentials are written owner-only. Both from code scanning.

## [0.5.0] - 2026-11-11

### Added
- The monitor: live accuracy from revert labels, Evidently drift reports, and a retrain trigger.
- The trainer pipeline: snapshot, validation, training, evaluation, registration, a promotion
  gate, a shadow period, and a post-promotion check with rollback.
- A purge of hidden revisions from kept snapshots, and retention for model versions and
  snapshots.
- Replays that show the loop working on recorded data: drift to promotion, and a poisoned
  snapshot rejected.

## [0.4.0] - 2026-11-09

### Added
- The Next.js frontend: landing page, live feed, review queue, edit detail with Explain, model
  leaderboard, and model health.
- A nonce-based content security policy on every page, an XSS payload corpus run through the
  real UI, axe accessibility checks, and Lighthouse budgets in CI.
- The single-seat gate in the UI, with `guest` and `user` accounts.

## [0.3.0] - 2026-11-08

### Added
- The scorer, with a fallback chain that keeps scoring when a model fails.
- The FastAPI service: review queue, edit detail, leaderboard, health, `/predict`, and
  `/explain` with prompt-injection defenses.
- A retrain-request poller, so the API never holds cluster credentials.
- A Compose end-to-end test of the whole pipeline.

## [0.2.0] - 2026-11-07

### Added
- Versioned dataset snapshots with a content hash, tracked with DVC.
- Five models (MLP, BiLSTM, DistilBERT, BERT, RoBERTa) trained on one snapshot with time-based
  splits, exported to ONNX with int8 quantization, and registered in MLflow.
- Evaluation with confidence intervals, calibration, slices by editor type, a golden set, and a
  robustness report. RoBERTa became champion with a test PR-AUC of 0.3641.

## [0.1.0] - 2026-11-05

### Added
- The ingestor, reading English Wikipedia's edit stream into Redpanda, and the labeler, which
  collects revert labels after 48 hours.
- The archiver, which writes the stream to parquet, and the purge and retention jobs.
- The database schema with least-privilege roles and row level security on every table.
- A 30-day backfill, and the first CI.
